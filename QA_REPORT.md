The unit runner transpiles the actual TypeScript test files and executes assertions with Node's assertion library. It does not resolve or typecheck installed third-party APIs. The separate source check is intentionally limited to fourteen processing roots.

The **isolated** UI harness executes actual application source with local React 18.2, while the production manifest declares React 19.2. Missing Motion, Radix, icon and utility dependencies are replaced by presentation adapters, and system fonts substitute for the declared fonts. Actual native MP4 playback, PCM-based waveform analysis and the shared Canvas renderer are used. Caption timestamps are explicit fixture intervals, not Whisper output.

The 21 checks include a one-word edit preserving all word intervals, all five caption presets, all three animation settings, real Canvas pixel differences for Blur/Fit/Fill, crop drag/reset, and the actual `Preview.tsx` cut-skip behavior versus Raw playback. Selecting 1080p was checked as a configuration change only, not an encoded-dimension result. Animation controls were checked as renderer inputs, not as verified Motion transitions.

**Processing screenshots use explicit state fixtures.** Ingest, analysis, export progress and completion are shown to review their design, not reported as successfully executed operations. The completion-state MP4 was rendered independently with native development tooling. It is not an export produced by the application, and that file is not included as a fake finished-app export. Every screenshot is visibly watermarked with its review scope.

The adapters, copied local React runtime and system font files are not included in the delivery. These checks do not establish focus trapping, actual Radix/Motion behavior, bundle correctness, speech or face inference, RNNoise execution, encoder correctness, or physical-device usability.

## RC2 hardening completed

Packet-continuous audio resampling now preserves the source clock across rate conversion, negative priming, delayed first packets and genuine timestamp gaps. Tests compare packet partitions and verify timing without restarting filters per decoded packet. Worker cancellation/error/message failures terminate jobs and detach callbacks. Ingest/voice/frame results are guarded against stale updates. Manual frame overrides are no longer replaced by late face results.

The speech model is pinned, and quota/private-cache failures degrade to uncached operation. Export probes the exact AAC configuration and rechecks after registering the official fallback. The finished-file validation includes AVC/AAC codecs, track presence, dimensions, start/end times, duration and three actual decoded frame samples. These new integration calls still need a real installed-library run.

Manual gestures derive from source and viewport geometry. Enhanced preview audio falls back to source audio on loading/playback failure instead of silently muting the video. Mobile touch targets and technical text, including desktop readouts, have been increased.

Three layers of browser tests are now defined: development fixture/export tests, **built production-site** tests, and a separate actual-model smoke suite. The required Chromium export gate fails when the encoder is missing rather than treating that as a pass. These suites are written but have not run with the real dependency installation.

## Implemented, still requiring integration proof

The source contains real calls for File-backed metadata/decode, audio extraction, worker analysis, Whisper inference and timestamps, face detection, RNNoise processing, Canvas caption/crop rendering, timestamped encoding, AAC fallback, muxing, MP4 validation and saving/sharing. These are not simulated progress timers or dummy export blobs. However, source implementation is not enough to certify that the current dependency set runs correctly in all those paths.

### High-priority risks

1. **Installed package/API compatibility.** Resolve packages, commit the actual lockfile, run strict typechecking and fix all errors. Current official APIs were researched (see `docs/API_REVIEW.md`), but only an installed build proves compatibility. The supplied semver ranges are not a reproducible lock.
2. **Actual encoder pipeline.** Run short with-audio and no-audio exports; confirm codec strings, track dimensions, output duration and decoder playback. Then exercise cuts, AAC fallback, rotated phone footage, long-GOP/VFR media and short final frames. Do not equate a nonempty Blob with a correct export.
3. **Audio timing.** Check priming, resampling at 44.1 kHz packet boundaries and RNNoise's assumed 480-frame latency. Use impulses/claps and a visible speech source. Measure drift at start, middle and end. Test linear seam blends for clicks, not just algebraic continuity.
4. **Speech runtime and model.** Verify the exact installed Transformers.js/ORT combination, local WASM files, GPU q4 word alignment, GPU-to-CPU retry, 24-second overlap ownership, download cancellation, offline cache reuse and cache clearing. The revision is now pinned; verify the artifact provenance and successful inference for that exact revision.
5. **MediaPipe 1.0.1.** Review the installed SDK's telemetry behavior and actual worker network requests. The implemented allowlist is defense in depth, not a complete proof against every transport a future SDK might use. Confirm its runtime scripts work under the production CSP.
6. **Memory and heat.** Measure 15/60/180-second phone clips, landscape 4K inputs, high-quality export, cancellation and repeated new projects. WAV preview and float buffers can create meaningful memory pressure despite bounded output and pooled frames. No physical thermal profiling has been performed.
7. **Accessibility and motion.** Test actual Radix focus return/trapping, keyboard tab/module navigation, touch targets, VoiceOver, reduced motion and real Motion layout animations. The private presentation harness cannot establish these.

## Known specification deviations

The bundled demo is original illustrated/synthetic media, not a real talking-head recording. HDR is rejected until tone mapping is verified, so some default phone-shot clips are not yet supported. Export is fixed 30 fps and speech audio is mono. Client preview uses native-video cut seeking and synchronized enhanced WAV playback, not a sample-accurate real-time audio graph; cut transitions and audio switching can differ perceptually from final rendering. Model sessions are freed after a job, so a later retry may reinitialize them from cached assets. No source-video persistence exists by design.

The architecture uses a common output-frame clock rather than retaining every arbitrary variable-rate source frame: each output tick maps to a source frame through the canonical EDL. This avoids cumulative rounding drift but resamples temporal cadence to 30 fps. Acceptance must include a VFR phone clip.

The source-link UI is wired to a supplied repository URL or inferred GitHub project page. There is no invented repository/live URL. Major external-library integration, deployment and physical-device requirements remain open.

## Required end-to-end acceptance

Use the same 60–90-second normal talking video, with three awkward pauses, two longer gaps and modest room noise, first in landscape and then portrait. Include standard phone MP4 and a supported MOV. Use a clear clap/visible sync cue near the start and end. Retain only rights-cleared test clips, never somebody else's private footage.

On current physical iPhone Safari, current Android Chrome, desktop Safari and desktop Chrome:

1. Open the production **repository subpath** without developer tools. Verify capability messaging before selection, including in-app-browser failure guidance.
2. Select the clip; check local metadata, orientation, actual waveform, detected pauses and real model-download progress. Record cold and warm runs.
3. Review Natural and Tight. Restore one cut. Check that speech edges remain intact and the output duration agrees with the canonical EDL.
4. Generate real English captions. Correct one word; verify preserved timing. Try all five styles and three animations, a long word, punctuation and safe-zone changes.
5. Enable voice processing; compare raw/enhanced at the same moment. Try Off/Light/Strong noise reduction. Listen for clicks, artifacts, clipping and delayed speech.
6. Enable 9:16 Auto. Move slightly; verify smoothed subject tracking. Force a no-face case and verify manual drag/zoom/center fallback. Test Fit/Blur/Square/Original.
7. Preview cut-aware pacing, then export 720p and (where probed supported) 1080p. Record elapsed time, any thermal warning and peak memory when instrumentation is available.
8. Save/share the actual MP4. Play the saved file from Photos or the phone's local media player, not only from the application's Blob URL. Inspect dimensions/codecs/duration, A/V sync, caption timing/animation and face position throughout.
9. Cancel each long stage and select another file. Confirm workers stop, no stale results replace the new project and the UI remains responsive. Repeat projects to detect leaks.
10. Capture network requests in a separate instrumented run. Confirm no source media, PCM, transcript or export is sent. Refresh and verify previous media is not recoverable from application-managed storage. Clear cached models and verify re-download behavior.

Repeat shorter 15-second and longer ~3-minute cases. Add no-audio, corrupted, unsupported-codec, oversized, >5-minute, quiet-speech and failed-model-download cases. A skipped browser codec test is NOT an acceptance pass.

## Release procedure

Run install/lock review, lint, full strict typecheck, Vitest, build, development Playwright, production Playwright and actual-model Playwright. Commands are documented in the README. The model suite is separate from normal fast CI because it intentionally downloads and executes real local inference. Upload the real logs as evidence. Complete the device/network/license protocol and attach dates, OS/browser versions, hardware, fixture checksums, output metadata and measured timings. Record the reviewed commit in `RELEASE_GATES.json`, then run `npm run verify:release`. Have a maintainer review the evidence before enabling the gated Pages deployment.

Until these checks are actually executed and passed, describe the deliverable as a source release candidate, not the completed production product requested in the specification.
