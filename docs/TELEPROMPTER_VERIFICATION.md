# Teleprompter verification

Checked on 13 September 2026 on Windows with Node v24.0.0, Chromium 1.63.0,
and the repository deployment base `/creator-autoedit/`. The test-only browser
run used Chromium's controlled fake camera and microphone flags; it never opened
the user's physical camera or microphone.

The final static checks passed:

- `npm run lint`
- `npm run typecheck`
- `npm test` — 19 files, 155 tests
- `npm run build` — built `dist/sw.js` and the Pages subpath artifact

The focused teleprompter checks passed:

- Read-only/prompt suite: 5/5. Initial studio open made no media, model, or
  network-write request; fixed/timed/manual controls, play/pause, cursor
  anchoring, WPM/font changes, mobile layouts, import, search, bookmark,
  backup, reload, and immediate close/reopen were exercised.
- Native capture suite: 1/1. Real `getUserMedia` tracks and native
  `MediaRecorder` produced a playable MP4 with camera and microphone tracks.
  The prompt auto-started with capture, pause left both tracks live, the reader
  overlay shared the viewfinder bounds, and a short frozen-`requestAnimationFrame`
  interval still committed non-empty media. Favourite, compare, retake, and
  original download were exercised.
- Recovery suite: quota fallback, stale interrupted-manifest recovery, and
  retake-after-script-edit all passed. A controlled IndexedDB
  `QuotaExceededError` never showed Saved and produced a non-empty recovery
  download; the completed take stayed playable after interrupted recovery.
- Built offline suite: 1/1. The worker registered at the repository subpath,
  precached the index/hashed JS/CSS/fonts/SVG shell, excluded WASM from the
  shell, and served an offline reload plus native recording from IndexedDB
  without preparing a model or making a write request.

The service worker is generated by [build-offline.mjs](../scripts/build-offline.mjs)
and registered only in production from [main.tsx](../src/main.tsx). Its shell
and runtime caches are scope-hashed, runtime WASM is cached only on first use,
non-GET and cross-origin requests bypass it, and it does not call `skipWaiting`
or force a reload during capture.

Evidence is in [teleprompter-evidence](teleprompter-evidence/README.md). Existing
source and model provenance remains in [SOURCES_PROMPTER.md](SOURCES_PROMPTER.md),
[SOURCES_CAPTURE.md](SOURCES_CAPTURE.md), [SOURCES_CAPTIONS.md](SOURCES_CAPTIONS.md),
and [PROMPT_MODEL_EVIDENCE.md](PROMPT_MODEL_EVIDENCE.md).

Physical macOS Safari, iPhone Safari, Android Chrome, thermal behavior, long
recordings, and hardware-specific codec/camera behavior remain untested.
Storage eviction and a browser crash can still lose an unflushed tail, so a
zero-loss crash guarantee is unavailable. Manual camera controls are exposed
only when `getCapabilities()` and `applyConstraints()` support them. Teeth
enhancement and a browser thermal sensor are unsupported and are not simulated.
